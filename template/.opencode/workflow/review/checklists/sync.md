# 文档与约束同步

从差异中找出行为、接口、配置字段与默认值、命令和参数、错误提示、权限与平台支持的变化。用 grep 查这些名称和规则在文档、变更记录、示例配置、技能与命令说明、代理说明及其他约束文件中的出现，核对改动后是否仍然成立。项目启用质量扩展时，读取其 quality.json 的 sync 登记（默认在 scripts/quality/），核对本批改动触发的关联，以及改名或删除后登记是否仍指向存在的文件；登记只是线索，没登记的关联同样要查。

只报告有位置和证据的不一致：某处与新行为矛盾、遗漏新增或删除的约束、同一规则在两处写法冲突，或面向用户的变化没有进入变更记录。不要求每次改动都改文档，措辞偏好不算发现。照着文档或配置去做会失败、误用或越权时阻断，按影响定级；遗漏说明、变更记录缺条目和补登记建议用不阻断的 P2/P3 发现提交；项目规则明确要求同步的按其要求定级。发现应登记而没登记的关联时，写出建议的 paths 和 related。
