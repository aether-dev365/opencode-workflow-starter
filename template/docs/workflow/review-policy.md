# 审核分级与结论

P0 是正在发生或必然发生的严重损失、泄露或大范围不可用；P1 是有可达触发路径的核心功能、数据或权限错误。两者阻断。

P2 是有限场景缺陷或具体测试缺口，按影响修复或明确登记延期；不能安全绕行或违背本次验收目标时仍阻断。P3 是非阻断的表达、风格或维护建议。

发现写明位置、触发条件、实际影响、证据、最小修复及验证。假设不当作事实，未测试不等于行为已坏。只查任务范围及实际关联，不顺便扩大存量重构。

pass 表示适用核查完成且无阻断，允许在 note 保留有依据的延期建议；findings 表示有阻断；incomplete 表示缺少必要证据或核查未完成。没读完不通过，必要缺口不能口头接受。关闭只表示本批次结束，不把 findings/incomplete 改成通过。

修复或补证后按相同累计 base 重建批次；空范围不是通过。未改变输入的可靠验证证据可以引用，但首版不自动沿用历史模型结论。

模型审核由用户请求或正式发布流程触发，普通提交不自动派审。静态检查、单测、集成和原生证据各有证明范围。

reviewer 的权限由插件强制为只读：只能使用 read、glob、grep 和 workflow_review_submit，在 reviewer.md 中放宽不会生效。reviewer.md 缺失或格式错误时，OpenCode 会忽略它，此时建批次和提交结论都会被拒绝。
