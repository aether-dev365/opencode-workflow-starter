# 开发与协作

先明确目标和验收。调查代码及现有约定，小改动直接实施；公共接口、新子系统或跨域变化先确认设计。缺少影响行为的决定时提问，能从代码核实的信息自行查明。

根 AGENTS.md 是入口，领域规则为单源。新增领域先登记 scopes.json 并验证规则加载；规则文件不要放在 `.opencode/agents`、`.opencode/commands` 等目录中，OpenCode 会把其中的 `.md` 加载为代理或命令。首次写入被拒时读取提示的规则，下一轮显式重试。插件上下文注入等价提供规则正文，但不代表模型可以忽略规则。

主代理统一需求、契约、拆分、集成、验证和提交。独立实现任务按所属领域选择 `onboarding.json` 中记录的实现类子代理，没有对应领域时用 `subagent` 的 `agent: implementer`，默认最多两个并行；共享文件指定唯一写入者。调查可用 explore，正式审核由 `/review` 派 reviewer。不要把通用技能中的实现角色机械映射成 general，否则不会使用已经选择的 implementer 模型。子代理拥有新上下文，父会话读过的规则和结论不能视为已传递。

模型在 `opencode.jsonc` 配置：根 `model` 是默认值，`agents.<名称>.model` 为单个代理指定，内置的 build、plan、explore、general 用同名 ID 覆盖，格式为 `provider/model` 或 `provider/model#variant`。通过 `/workflow-setup` 为 implementer、reviewer 和新增子代理明确选择动态继承或固定模型：继承会跟随发起会话的模型和思考强度，固定当前 ID 则不会随主会话切换；固定时不写 `#variant` 就使用模型默认的思考强度。模型只在原生配置中生效，不在代理文件里重复；onboarding.json 记录选择意图，宿主核对最终生效结果。reviewer 可选择不同模型获取不同视角，但只有一个可用模型时可以明确继承，不必制造重复配置。额度、认证或上级配置不符合选择时，解释冲突后重新选择，不自动换模型。

任务卡包含：目标和验收、绝对 Location/基线、写入范围、契约/依赖、验证命令和资源、交付格式。实现者不提交、不发布、不访问生产、不继续派发。

工作树只隔离文件；相同数据库、端口、设备和构建缓存可能仍冲突，必须独占或串行。收到停滞提醒后先核实际会话与进程，确认旧执行终止再接手，不根据父会话空闲猜测完成。

OpenCode V2 会沿 Location 的全部祖先发现插件。在 `.worktrees/<名称>` 下，主检出和工作树里的两份 `workflow.starter` 会同时被发现并报 Duplicate plugin ID，实际运行的是祖先检出那份。

工作树里修改的插件代码须用隔离原生验收验证，不能把祖先插件 active 当成本工作树实现已生效；不要通过改插件 ID 或关闭守卫绕过。已有工作树的 `opencode.jsonc` 各自独立，主检出的修改不会同步过去，需要手动同步后重新加载。

交付前核实际 diff、行为变化、适用测试、文档和配置联动。按项目约定的提交格式（接入时在此写明）提交单一范围的改动；暂存、凭据扫描和提交分清步骤。不要擅自推送或发布。

手动审核由用户触发 `/review`；普通实现不自动派 reviewer。基础模式未安装外部技能时遵循本文即可。完整模式先通过接入向导确认 Superpowers 实际可用，再按任务加载设计、计划或调试技能；缺失时修复或明确切回基础模式，不模拟已使用技能。阶段自检不能替代本套件正式审核，也不自动授权额外多代理调用。
